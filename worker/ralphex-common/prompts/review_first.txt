# Shared first-review prompt for both the Codex and Pi profiles.

Code review of: {{GOAL}}

Progress log: {{PROGRESS_FILE}} (contains task execution and previous review iterations)

## Step 1: Get Branch Context

Run both commands to understand what was done:
- `git log {{DEFAULT_BRANCH}}..HEAD --oneline`
- `git diff {{DEFAULT_BRANCH}}...HEAD`

## Step 2: Launch ALL 6 Review Agents IN PARALLEL

CRITICAL: All 6 agent invocations MUST be issued in a single message for true
parallel execution. These agents are fully independent — no shared state, no
dependencies, and no ordering requirements.

Under the Codex executor, do not serialize `spawn_agent` calls: emit them all
in one response, then wait for the full set. Under a Claude-compatible
executor, issue foreground Task tool calls in one message; do not use
background tasks.

CRITICAL: Do not proceed until every agent has returned. Do not embed code or
diffs in the agent prompts; the agent expansions direct them to inspect the
branch themselves.

{{agent:quality}}
{{agent:implementation}}
{{agent:testing}}
{{agent:simplification}}
{{agent:documentation}}
{{agent:thermonuclear_quality}}

## Step 3: Collect, Verify, and Fix Findings

Merge duplicates. For each finding, read its context, verify it is real, and
check for existing mitigations. Fix every confirmed issue, run the required
tests and linters, then commit fixes with `fix: address code review findings`.
Do not dismiss an issue merely because it predates this branch.

## Step 4: Signal Completion

SIGNAL LOGIC — read carefully, and decide only after Steps 1-3 are fully done:

`REVIEW_DONE` means this iteration found zero confirmed issues, not that fixes
were completed.

- Path A — no confirmed issues found: output exactly `<<<RALPHEX:REVIEW_DONE>>>`.
- Path B — issues found and fixed: stop with no signal at all. Do not output
  `REVIEW_DONE`. The external loop runs another review iteration to verify
  your fixes, since they might have introduced new issues.
- Path C — confirmed issues found that cannot be fixed: output exactly
  `<<<RALPHEX:TASK_FAILED>>>`.

Do not write the literal signal tokens anywhere except as that one final,
standalone line when a path calls for one. In particular, never quote or
restate `<<<RALPHEX:TASK_FAILED>>>` or `<<<RALPHEX:REVIEW_DONE>>>` while
reasoning about which path applies — ralphex scans the whole response for
these tokens, so quoting one elsewhere is indistinguishable from signaling it
and will be misread as that outcome even when you took a different path.

Output format: no Markdown formatting in the response text.
