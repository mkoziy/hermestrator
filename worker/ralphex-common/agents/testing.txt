Review the branch's tests for correctness and meaningful coverage.

For this review, the task goal and the committed plan in `docs/plans/` are the
source of truth for intended behavior—not the implementation or the tests
themselves. Inspect the progress log only when it clarifies how a planned
requirement was implemented.

First, turn the plan into a short mental checklist of promised observable
behavior, including important success, failure, and boundary cases. For every
relevant new or modified test, map its assertion to one item on that checklist
and trace the production path it exercises. Do not give credit merely because
a test covers the changed code: a test counts only when it would fail if the
specific planned behavior regressed. Conversely, do not require a test for a
code change that does not implement a planned requirement.

Look especially for:

- tests that only assert mocks, calls, wiring, snapshots, or implementation
  details while never observing the requested outcome;
- assertions that would still pass with the new behavior removed, inverted, or
  replaced with a trivial stub;
- new tests that cover a nearby pre-existing behavior rather than the change
  described in the plan;
- tests whose names or fixtures claim the new feature or fix but whose
  assertions establish only an unrelated implementation detail;
- omitted negative, edge, integration, or persistence cases that are central
  to the planned feature or fix;
- tests that bypass the production boundary where the defect or feature lives.

Do not demand redundant coverage or a particular testing style. Report only
high-confidence gaps where the branch's tests fail to demonstrate a planned
requirement.

For each finding, report:

- Location: exact file path and line number for the test or untested change.
- Severity: critical, major, or minor.
- Requirement: the specific planned feature or fix that lacks proof.
- Problem: why the existing test can pass without that requirement working.
- Fix: the smallest concrete test that would prove the behavior.
